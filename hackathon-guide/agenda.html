From idea

to live website.

Setup / około 10 minut ✓ GotowePrzygotuj środowisko

Pobierz starter, otwórz właściwy folder w Claude, przygotuj Node.js i uruchom lokalny podgląd. Figmę podłącz tylko wtedy, gdy chcesz z niej importować materiały.

Pobierz i rozpakuj starter Astro

Pobierz paczkę, rozpakuj ją w łatwym do znalezienia miejscu i nazwij folder według produktu, np. nazwa-produktu-landing.

Pobierz starter (ZIP)
Otwórz Claude i wskaż folder projektu ze starterem astro

Uruchom Claude i wskaż dokładnie folder, w którym znajduje się rozpakowany starter Astro. Przed każdym promptem upewnij się, że pracujesz w prawidłowym projekcie.

Otwórz terminal w Claude i zainstaluj Node.js

Po otwarciu projektu uruchom terminal w prawym górnym rogu Claude. Możesz też użyć aplikacji Terminal na swoim komputerze — wtedy najpierw przejdź do folderu projektu.

Wybierz polecenie odpowiednie dla swojego systemu.

macOS / Homebrew
brew install node
Windows / winget
winget install OpenJS.NodeJS.LTS
Sprawdź instalację
node --version
npm --version

Poprawny wynik pokazuje numer wersji Node.js rozpoczynający się od v oraz numer npm. Jeżeli polecenie nie istnieje albo nie zwraca numerów wersji, zgłoś problem prowadzącemu.

Uruchom projekt w terminalu

W Claude otwórz projekt, do którego wcześniej wskazałeś folder ze starterem Astro. Kliknij ikonę terminala w prawym górnym rogu okna Claude, aby otworzyć konsolę. Upewnij się, że terminal pracuje w folderze startera, w którym znajduje się plik package.json. Przy pierwszym uruchomieniu zainstaluj zależności projektu:

Terminal / instalacja zależności (Astro i Vite)
npm install

Vite instaluje się razem z zależnościami Astro. Nie musisz mieć go wcześniej na komputerze ani instalować go globalnie. Poczekaj, aż npm install zakończy się poprawnie i terminal będzie gotowy na kolejne polecenie.

W tej samej konsoli wpisz npm run dev i naciśnij Enter. To polecenie uruchomi lokalny podgląd startera Astro:

Terminal / uruchomienie projektu
npm run dev

Po chwili terminal powinien wyświetlić odpowiedź podobną do tej:

Przykładowa odpowiedź Astro
astro v5.x.x ready in 320 ms

┃ Local    http://localhost:4321/
┃ Network  use --host to expose

Skopiuj adres widoczny przy Local, np. http://localhost:4321/. Jeżeli terminal pokaże inny port, użyj adresu wyświetlonego u siebie.

Połącz Figmę z Claude przez plugin / MCP(opcjonalnie)

Zrób to tylko wtedy, gdy chcesz przenosić z Figmy elementy wizualne, ikony, assety lub fragmenty designu. W Claude otwórz Plugins, wybierz Figma i przejdź autoryzację na koncie, na którym znajduje się właściwy projekt.

Jeżeli nie potrzebujesz Figmy albo integracja nie działa, pomiń ten punkt. Asset możesz wyeksportować ręcznie i umieścić bezpośrednio w folderze projektu.

Otwórz starter w przeglądarce

Terminal podaje adres podglądu w wierszu Local, na przykład http://localhost:4321/. Kliknij ten adres w terminalu Claude lub skopiuj go i wklej w pasku adresu przeglądarki. Jeśli terminal pokazuje inny port, użyj dokładnie podanego adresu. Sprawdź, czy strona startowa działa. Nie zamykaj terminala z uruchomionym serwerem. Gdy widzisz podgląd, przejdź do kroku 2.

Strategia i wireframe / około 20 minut ✓ GotoweZaimportuj strategię i zbuduj pierwszą wersje strony

Najpierw przekaż agentowi kontekst produktu. Następnie poproś o propozycję 2–3 sekcji, wybierz kierunek i dopiero wtedy zleć budowę strukturalnej bazy strony.

Załącz brief.md w nowym wątku

Z poniższej listy wybierz pakiet plików dla produktu, nad którym pracowałeś pierwszego dnia hackathonu: Aescape Atlas, Catch, Almanac lub Undo. Pobierz odpowiedni ZIP i rozpakuj go — w środku znajdziesz plik pakiet/brief.md, który załączysz w nowym wątku. Jeżeli strategia produktu uległa zmianie podczas pracy pierwszego dnia, przygotuj osobny plik Markdown z jej uzupełnieniem — opisz w nim zmiany i nowe ustalenia.

Otwórz nowy wątek w Claude w projekcie startera. Załącz plik pakiet/brief.md z wybranego pakietu oraz plik z uzupełnieniem, jeśli go przygotowałeś, i wklej poniższy prompt. Agent ma uzupełnić właściwe pliki startera, ale jeszcze niczego nie projektować.

Prompt 01 / z briefu do strategii
Użyj lokalnego skilla astro-strategy-build. Na podstawie załączonego pakiet/brief.md przygotuj spójną strategię pod anglojęzyczny landing page prezentujący i promujący produkt — również wtedy, gdy brief opisuje aplikację lub ekran urządzenia. Jeśli dołączam uzupełnienie, uwzględnij je jako aktualizację.

To projekt testowy na hackathon. Uzupełnij luki przemyślanymi założeniami dotyczącymi odbiorców, pozycjonowania, wartości, języka i oferty. Możesz stworzyć przykładowe ceny, metryki i fikcyjne opinie, jeśli wspierają koncepcję. W dokumentach odróżnij informacje z briefu od założeń i danych demonstracyjnych; nie przypisuj wymyślonych opinii rzeczywistym osobom ani firmom. Traktuj te założenia jako przyjęte do dalszej pracy nad prototypem. Nie zadawaj pytań o brakujące dane ani nie prowadź researchu. Sprzeczności rozstrzygnij spójną decyzją roboczą i krótko ją odnotuj.

Zapisz oryginalny brief bez zmian i przygotuj strategię w tych plikach, względem głównego folderu projektu:
- project-context/research/source-brief.md — oryginalny brief;
- project-context/audiences/icp.md — odbiorcy, potrzeby i motywacje;
- project-context/value-proposition/value-proposition.md — wartość i wyróżniki;
- project-context/brand-foundations/strategy.md — pozycjonowanie i strategia produktu;
- project-context/brand-foundations/tone-of-voice.md — język i zasady komunikacji;
- project-context/content/product-brief.md — uporządkowany brief i cel landing page’a;
- project-context/business-model/business-context.md — oferta i model biznesowy, jeśli mają znaczenie dla koncepcji.
Zaktualizuj project-context/context-index.json, zachowując jeden stabilny identyfikator produktu oraz rozróżnienie źródeł i założeń.

Strategię opracuj po polsku, a przykłady tekstów strony po angielsku. Nie zmieniaj wizualnych zasad Mecha ani brand.md. Nie proponuj jeszcze IA i nie pisz kodu. Na końcu krótko podsumuj zapisane pliki i najważniejsze przyjęte założenia.
Poproś o propozycję architektury informacji

Poproś AI o krótki plan. Na tym etapie wybierasz, co landing page ma powiedzieć — agent nie powinien jeszcze pisać kodu.

Prompt 02 / architektura informacji i wizuale
Użyj lokalnego skilla astro-strategy-analysis. Przeczytaj project-context/context-index.json i tylko potrzebne dokumenty strategiczne, które wskazuje. Surowy brief doczytaj wyłącznie dla konkretnej luki lub sprzeczności; nie przeszukuj komponentów, CSS ani dokumentacji Design Systemu.

Zaproponuj architekturę informacji anglojęzycznego landing page’a: trzy sekcje, a czwartą tylko wtedy, gdy wnosi wyraźną wartość. Maksymalnie cztery sekcje łącznie z hero i końcowym CTA. Oprzyj propozycję na strategii oraz przyjętych założeniach i danych demonstracyjnych prototypu. Nie wracaj do pytań o ich potwierdzenie.

Dla każdej sekcji podaj:
1. miejsce w kolejności, cel i jeden główny komunikat;
2. propozycję nagłówka, krótkiego copy i CTA, jeśli jest potrzebne;
3. propozycję wizuala oraz konkretny brief assetu do stworzenia: co przedstawia, jak wspiera komunikat, jego kompozycję, orientacyjne proporcje i sposób wykonania, np. grafika generowana, mockup ekranu lub diagram HTML/CSS;
4. sposób przejścia do kolejnej sekcji.

Proponuj, co stworzyć dla danej sekcji, zamiast wyliczać brakujące materiały. Jeśli obraz nie jest potrzebny, zaproponuj kompozycję opartą na typografii, liczbach lub prostym schemacie. Brak gotowych assetów nie blokuje IA.

Przedstaw zwięzłą, numerowaną propozycję w rozmowie. Copy strony napisz po angielsku, uzasadnienia i briefy assetów po polsku. Na tym etapie nie zapisuj plików, nie pisz kodu i nie generuj assetów. Zakończ krótkim uzasadnieniem kolejności sekcji.
Zleć budowę struktury sekcji

W tym samym wątku, w którym omówiłeś i zatwierdziłeś architekturę informacji, wklej poniższy prompt. AI zbuduje pierwszą wersję sekcji na podstawie strategii marki i ustalonego planu strony — nie musisz ponownie go wklejać.

Na tym etapie AI samodzielnie dobierze kolory z palety marki, układ sekcji i rozmieszczenie treści, korzystając z istniejącego design systemu oraz zasad w brand.md. Potraktuj rezultat jako punkt wyjścia. Gdy sekcje będą gotowe, przejdziesz do kreatywnej iteracji: ocenisz propozycję i dopracujesz ją z AI, sekcja po sekcji.

Prompt 03 / budowa struktury sekcji
Zbuduj pierwszą działającą wersję struktury sekcji landing page’a według architektury informacji zaakceptowanej wyżej w tej rozmowie. Zachowaj uzgodnione sekcje, ich kolejność, cele i zakres; nie proponuj IA ponownie. Zapisz krótki plan w project-context/content/page-plan.md i wdroż stronę główną na /, w src/pages/index.astro. Nie twórz dodatkowej trasy.

Wszystkie teksty strony przygotuj po angielsku, zgodnie ze strategią, tone of voice i ustaleniami z rozmowy. Korzystaj z przyjętych założeń i danych demonstracyjnych prototypu bez ponownego pytania o ich zatwierdzenie. Zachowaj informację o ich pochodzeniu w dokumentach strategicznych.

Stosuj lokalne instrukcje projektu: starter określa sposób budowania interfejsu, komponenty swoje API i zachowanie, a Mecha wygląd. Dobierz istniejące komponenty i Website Patterns do potrzeb sekcji, a następnie sprawdź dokładne API wybranych elementów. Wspólną grupę nagłówka, tekstu i akcji buduj przez Content, gdy pasuje do układu. Gdy pattern nie pasuje, użyj lokalnego HTML/CSS oraz systemowych variables.

Korzystaj z systemowych struktur layoutu i właściwych kategorii variables: gap dla dzieci grupy, space dla odstępów w przepływie, content-padding dla wnętrza powierzchni oraz section-padding dla sekcji. Odstęp ustawiaj na właściwym rodzicu i nie dubluj go marginesem dziecka. Dobieraj pozostałe variables zgodnie z ich przeznaczeniem. Zachowaj typografię, kolory i wygląd komponentów Mecha z brand.md; przykłady marki nie ograniczają geometrii sekcji. Samodzielnie dobierz kolory z istniejącej palety marki, układ sekcji i rozmieszczenie treści, zachowując zatwierdzoną IA. W ramach budowy strony nie zmieniaj globalnego API komponentów ani nie twórz nowych publicznych tokenów.

Wykorzystaj dostępne assety zgodnie z planem wizuali. Dla brakujących obrazów zachowaj docelową geometrię przez systemowy placeholder; prosty diagram lub mockup możesz zbudować lokalnie w HTML/CSS. Generowanie obrazów pozostaw do osobnego polecenia. Brak gotowych grafik nie blokuje budowy.

Zachowaj BaseLayout, ComponentInfoLayer oraz kontrolki grid guides i dokumentacji Design Systemu w prawym dolnym rogu. Korzystaj z serwera uruchomionego dla tego projektu albo uruchom go zgodnie z konfiguracją i podaj adres z terminala. Projekt nie wymaga Git.

Przygotuj responsywną bazę do wspólnej oceny i dalszej kreatywnej iteracji sekcja po sekcji. Sprawdź stronę na desktopie 1440×900 i mobile 390×844: odstępy między nagłówkiem, treścią, akcjami i mediami, overflow oraz podstawowe interakcje. Podczas kontroli interakcji wyłącz guides. Wykonaj proporcjonalną walidację zgodnie z instrukcjami projektu, bez produkcyjnych audytów. Na końcu krótko podsumuj zmiany, wynik sprawdzenia i miejsca z placeholderami.

To zadanie może potrwać kilka lub kilkanaście minut. Nie czekaj bezczynnie — przejdź od razu do kroku 3 i zacznij zbierać inspiracje.

Narzędzia do animacji na webie

Wybierz narzędzie pod efekt, który chcesz osiągnąć. Poniżej znajdziesz biblioteki i edytory, które możesz wykorzystać podczas hackathonu — każdy link prowadzi do oficjalnej strony lub dokumentacji.

GSAP + ScrollTriggerDo skoordynowanych wejść tekstów i obrazów, przypinanych sekcji oraz animacji sterowanych przewijaniem. Przykład: opowieść o produkcie odsłaniana krok po kroku podczas scrollowania.(Sekwencje i scroll) MotionDo animacji elementów HTML i SVG, przejść oraz efektów powiązanych ze scrollem. Przykład: delikatne wejścia kart i animowane wskaźniki. W Astro możesz użyć wersji JavaScript.(Interakcje UI) Anime.jsDo animowania elementów strony i SVG w sekwencjach. Przykład: rysowanie linii diagramu procesu lub kaskadowe pojawianie się elementów kompozycji.(SVG i sekwencje) Three.jsDo tworzenia scen 3D w przeglądarce: modeli, oświetlenia, kamer i efektów przestrzennych. Przykład: obracany model produktu albo interaktywny wizual w hero. Wymaga przygotowania sceny w kodzie.(3D w kodzie) SplineDo projektowania interaktywnych scen 3D w wizualnym edytorze i osadzania ich na stronie. Przykład: obiekt w hero reagujący na ruch kursora lub kliknięcie.(3D w edytorze) RiveDo ilustracji i animowanych elementów reagujących na działania użytkownika. Przykład: postać reagująca na formularz albo ilustracja zmieniająca stan po kliknięciu. Przygotuj animację w Rive i osadź ją przez web runtime.(Interaktywne ilustracje) Lottie / dotLottieDo odtwarzania przygotowanych animacji Lottie na stronie. Przykład: animowana ikona, loader lub ilustracja w sekcji korzyści. Potrzebujesz pliku animacji oraz odtwarzacza webowego.(Gotowe animacje) LenisDo wygładzania przewijania strony, także w połączeniu z animacjami scrollowymi. Przykład: płynne przechodzenie przez narracyjny landing page. Sam Lenis nie tworzy animacji elementów ani scen 3D.(Płynne przewijanie)

Na start wybierz jeden efekt i jedno narzędzie. Opisz AI, co ma się poruszać, co uruchamia animację i jak ma wyglądać jej stan końcowy. Do prostego hovera wystarczy CSS; do rozbudowanej sekwencji rozważ GSAP, a do wizualu 3D — Three.js lub Spline. Poproś o wdrożenie w starterze Astro, sprawdzenie na mobile i uwzględnienie preferencji ograniczonego ruchu.

Gdy pierwsza wersja sekcji będzie gotowa, załącz wybrane materiały do Claude i opisz, jaki efekt chcesz uzyskać. Możesz na przykład:

  • Wklejać inspiracje z Pinteresta i wskazywać, co chcesz z nich wykorzystać: kompozycję, typografię, klimat lub sposób prezentacji produktu.
  • Tworzyć proste szkice struktury sekcji i załączać je jako wskazówkę dotyczącą układu.
  • Przygotowywać w Figmie klatki kluczowe animacji — stan początkowy, kolejne etapy i stan końcowy — oraz opisywać przejścia między nimi.
  • Załączać benchmarki innych stron lub komponentów i wyjaśniać, które rozwiązania chcesz zaadaptować.
  • Opisywać własnymi słowami oczekiwany rezultat: co ma się pojawić, gdzie, w jakiej kolejności i jak ma się zachowywać.

Aby precyzyjniej opisać rozmieszczenie elementów w swoim podglądzie startera, włącz Grid Guides w prawym dolnym rogu. Odwołuj się do widocznych kolumn, np. „Umieść nagłówek w kolumnach 1–5, a wizual w kolumnach 7–12”. Dopasuj numery do siatki wyświetlanej w Twoim projekcie.

Traktuj inspiracje jako wskazówki do własnego rozwiązania, zgodnego z brandingiem projektu. Nie proś o bezpośrednie kopiowanie całej strony.

Iteruj sekcja po sekcji w Claude

Włącz Grid Guides. Gdy chcesz zmienić element, podaj nazwę komponentu, przytocz charakterystyczny tekst z danej sekcji albo dołącz jej screen. Przy zmianach layoutu określaj dokładnie, od której do której kolumny ma znajdować się każdy element.

Każdy prompt kieruj do jednej sekcji, komponentu albo animacji. Możesz pracować w 2–3 wątkach równolegle, jeśli ich zakresy nie dotykają tych samych plików i elementów.

Z praktyki / hero na podstawie screena
Zrób sekcję hero tak jak na screenie: u góry nagłówek z większym paddingiem od góry, a na dole visual na całą szerokość ekranu.
Z praktyki / podmiana visuala
Użyj tego visuala w sekcji hero.
Z praktyki / animacja visuala przy scrollowaniu
Ustaw dla visuala w hero animację skalowania zdjęcia przy scrollowaniu. Po wejściu na stronę visual jest mały i przyklejony do prawej strony. Gdy scrolluję, zwiększa swoją szerokość, aż wypełni całą szerokość ekranu. Przez całą animację zachowaj proporcje 16:9.
Z praktyki / asymetryczna sekcja ze statystykami
Ustaw sekcję ze statystykami tak, żeby content startował od 7. kolumny, jak na załączonym screenie. Chodzi o taką asymetryczną kompozycję — po lewej tylko mały tekst w eyebrow.
Z praktyki / przesunięcie nagłówka w CTA
W komponencie „Component name: CallToAction” ustaw jednak heading tak, żeby zaczynał się od 4. kolumny.
Z praktyki / mapa w sekcji CTA
W sekcji CTA zaznaczyłem na screenie pomarańczowy blok. W tym miejscu chciałbym mieć mapę z pinezkami nawiązującą do „Live in 150+ locations, including Equinox and Ritz-Carlton.”

Mapa może być interaktywna. Nie zamykaj jej w osobnym wrapperze — ma być bardziej organicznie dodana do layoutu. Załączam benchmark: chodzi o mapę na stroke’u, z samym obrysem, podobnie jak assety SVG w naszym systemie.

Dodaj mapę w zaznaczonym miejscu i zwiększ wysokość całej sekcji.
Z praktyki / większa typografia w projekcie
Zwiększ w projekcie skalę typograficzną nagłówków. Chcę większą typografię, bardziej w stylu display.
Szybki poradnik

Jak sprawnie budować z AI

Pracuj maksymalnie w 2–3 wątkach

Osobne wątki mogą dotyczyć np. copy, assetu i animacji. Nie otwieraj kilkunastu rozmów, nad którymi trudno zapanować.

Rozdzielaj zakresy

Nie zlecaj dwóm agentom jednoczesnej zmiany tego samego komponentu, pliku ani wspólnych tokenów.

Opisuj konkretny rezultat

Podaj nazwę komponentu, charakterystyczny tekst z sekcji albo dołącz jej screen. Dodaj cel zmiany, kolumny gridu i elementy, których agent nie powinien ruszać. „Zrób ładniej” nie wystarczy.

Dobieraj model do zadania

Mocniejszego modelu używaj do strategii, architektury, komponentów i animacji. Szybszy wystarczy do copy, spacingu i drobnych poprawek.

Nie czekaj bezczynnie

Gdy agent buduje wireframe, zbieraj inspiracje, rób screenshoty i przygotowuj assety do kolejnej iteracji.

Inspiracja potrzebuje instrukcji

Wklejając referencję do Claude, napisz, czy chodzi o kompozycję, typografię, motion, asset czy zachowanie komponentu.

Iteruj małymi zmianami

Przed większą zmianą upewnij się, że projekt działa. Pracuj sekcja po sekcji i po każdej zmianie sprawdzaj efekt w przeglądarce.

Problem techniczny? Zgłoś go

Jeżeli projekt nie startuje, terminal pokazuje błąd albo integracja nie działa, zgłoś to prowadzącemu zamiast tracić dużą część warsztatu na diagnozę.
