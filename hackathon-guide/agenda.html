A hands-on guide to building with Astro & AI

From idea

to live website.

Setup / około 10 minut ✓ GotowePrzygotuj środowisko

Pobierz starter, otwórz właściwy folder w Claude, przygotuj Node.js i uruchom lokalny podgląd. Figmę podłącz tylko wtedy, gdy chcesz z niej importować materiały.

Pobierz i rozpakuj starter Astro

Pobierz paczkę, rozpakuj ją w łatwym do znalezienia miejscu i nazwij folder według produktu, np. nazwa-produktu-landing.

Pobierz starter — link do uzupełnienia
Otwórz Claude i wskaż folder projektu

Uruchom Claude i wskaż dokładnie folder, w którym znajduje się rozpakowany starter Astro. Przed każdym promptem upewnij się, że pracujesz w prawidłowym projekcie.

Otwórz terminal w Claude i zainstaluj Node.js

Po otwarciu projektu uruchom terminal w prawym górnym rogu Claude. Możesz też użyć aplikacji Terminal na swoim komputerze — wtedy najpierw przejdź do folderu projektu.

Wybierz polecenie odpowiednie dla swojego systemu.

macOS / Homebrew
brew install node
Windows / winget
winget install OpenJS.NodeJS.LTS
Sprawdź instalację
node --version
npm --version

Poprawny wynik pokazuje numer wersji Node.js rozpoczynający się od v oraz numer npm. Jeżeli polecenie nie istnieje albo nie zwraca numerów wersji, zgłoś problem prowadzącemu.

Połącz Figmę z Claude przez plugin / MCP(opcjonalnie)

Zrób to tylko wtedy, gdy chcesz przenosić z Figmy elementy wizualne, ikony, assety lub fragmenty designu. W Claude otwórz Plugins, wybierz Figma i przejdź autoryzację na koncie, na którym znajduje się właściwy projekt.

Jeżeli nie potrzebujesz Figmy albo integracja nie działa, pomiń ten punkt. Asset możesz wyeksportować ręcznie i umieścić bezpośrednio w folderze projektu.

Uruchom projekt w terminalu

W terminalu otwartym dla folderu projektu wpisz poniższe polecenie i naciśnij Enter.

Terminal / uruchomienie projektu
npm run dev

Po chwili terminal powinien wyświetlić odpowiedź podobną do tej:

Przykładowa odpowiedź Astro
astro v5.x.x ready in 320 ms

┃ Local    http://localhost:4321/
┃ Network  use --host to expose

Skopiuj adres widoczny przy Local, np. http://localhost:4321/. Jeżeli terminal pokaże inny port, użyj adresu wyświetlonego u siebie.

Otwórz starter w przeglądarce

Wklej lokalny adres w pasku przeglądarki i sprawdź, czy strona startowa działa. Nie zamykaj terminala z uruchomionym serwerem. Gdy widzisz podgląd, przejdź do kroku 2.

Strategia i wireframe / około 20 minut ✓ GotoweZaimportuj strategię i zbuduj wireframe

Najpierw przekaż agentowi kontekst produktu. Następnie poproś o propozycję 2–3 sekcji, wybierz kierunek i dopiero wtedy zleć budowę strukturalnej bazy strony.

Załącz strategię w nowym wątku

Wybierz pakiet strategiczny, z którego korzystałeś poprzedniego dnia, i rozpakuj pobrany ZIP. Jeżeli strategia uległa zmianie, przygotuj osobny plik Markdown z jej uzupełnieniem — opisz w nim zmiany i nowe ustalenia.

Otwórz nowy wątek w Claude w projekcie startera. Załącz plik pakiet/brief.md z wybranego pakietu oraz plik z uzupełnieniem, jeśli go przygotowałeś, i wklej poniższy prompt. Agent ma uzupełnić właściwe pliki startera, ale jeszcze niczego nie projektować.

Pobierz Aescape Atlas (ZIP) Pobierz Catch (ZIP) Pobierz Almanac (ZIP) Pobierz Undo (ZIP)
Prompt 01 / import strategii
Przeczytaj załączony brief z pakietu strategicznego, z którego korzystałem podczas pierwszego dnia. Jeśli załączam również plik z uzupełnieniem strategii, uwzględnij opisane w nim zmiany i nowe ustalenia jako aktualizację briefu. Jeżeli dokumenty są sprzeczne, a uzupełnienie nie rozstrzyga konfliktu, wskaż go przed zapisaniem kontekstu. Najpierw zapoznaj się z dokumentacją startera i regułami dotyczącymi plików strategicznych.

Przenieś istotny kontekst produktu do właściwych plików w projekcie. Oddziel potwierdzone fakty, założenia i brakujące informacje. Nie twórz jeszcze interfejsu ani nowych komponentów.

Na końcu podsumuj, jakie pliki utworzyłeś lub zmieniłeś, oraz wskaż luki, które mogą wpłynąć na komunikację landing page’a.
Poproś o propozycję architektury informacji

Poproś AI o krótki plan. Na tym etapie wybierasz, co landing page ma powiedzieć — agent nie powinien jeszcze pisać kodu.

Prompt 02 / propozycja sekcji
Na podstawie plików strategicznych produktu zaproponuj architekturę informacji dla landing page’a składającego się z 2–3 sekcji. Sekcje mają jasno komunikować wartość produktu i promować go właściwemu odbiorcy.

Dla każdej sekcji podaj:
1. cel komunikacyjny,
2. jeden główny komunikat,
3. potrzebną treść, dowód lub asset,
4. sposób przejścia do kolejnej sekcji.

Przedstaw wynik jako krótką, numerowaną listę. Nie pisz kodu, nie buduj jeszcze strony i nie dodawaj niepotwierdzonych informacji.
Zleć budowę wireframe’u

Wklej wybrany i ewentualnie poprawiony wariant architektury. Agent ma zbudować działającą bazę, którą dopracujesz wizualnie w kolejnym kroku.

Prompt 03 / budowa wireframe’u
Zbuduj wireframe landing page’a na podstawie poniższej, zatwierdzonej architektury informacji:

[WKLEJ TUTAJ WYBRANY PLAN 2–3 SEKCJI]

Stwórz strukturalną bazę tych sekcji. Korzystaj z istniejących komponentów, tokenów, assetów, brandingu i agentic rules startera Mecha. Zachowaj obecny system zamiast tworzyć równoległe style. Użyj treści wynikających z plików strategicznych i nie wymyślaj brakujących faktów.

Na tym etapie skup się na hierarchii, układzie i przepływie informacji — bez pełnego dopracowania wizualnego. Po implementacji sprawdź działanie strony w przeglądarce i podsumuj zmienione pliki.

To zadanie może potrwać kilka lub kilkanaście minut. Nie czekaj bezczynnie — przejdź od razu do kroku 3 i zacznij zbierać inspiracje.

Praca kreatywna / główny blok ✓ GotoweZnajdź inspiracje i iteruj

W czasie budowy wireframe’u zbierz kierunek wizualny. Gdy baza będzie gotowa, rozwijaj ją małymi zmianami zgodnie z workflow startera pokazanym przez prowadzącego w kroku 0.

Znajdź i zbierz inspiracje

Szukaj konkretnych rozwiązań: kompozycji sekcji, sposobu pokazania produktu, zachowania typografii, animacji albo gotowej techniki. Otwieraj przydatne strony w nowych kartach, rób screenshoty i zapisuj assety oraz linki w jednym lokalnym folderze.

Gdy wireframe będzie gotowy, załącz wybrane materiały do Claude i opisz, jaki efekt chcesz uzyskać: kompozycję, typografię, motion, asset albo sposób prezentacji produktu. Nie proś o bezpośrednie kopiowanie całej strony.

Przykład / sekcja procesu ze screena
Załączam screen z inspiracją pokazującą, jak chcę, żeby wyglądała sekcja procesu na moim landing page’u.

Na podstawie tego screena zbuduj sekcję „Proces” w miejscu komponentu `[IDENTYFIKATOR SEKCJI]`. Potraktuj referencję jako wskazówkę dla struktury: układu nagłówka i opisu, rozmieszczenia kroków, ich numeracji, odstępów oraz sposobu połączenia ich w czytelną sekwencję.

Dopasuj tę strukturę do treści mojego produktu oraz istniejących komponentów, tokenów i brandingu Mecha. Korzystaj z zatwierdzonych treści i plików strategicznych projektu. Nie kopiuj tekstów, logo ani identyfikacji wizualnej z inspiracji. Jeżeli brakuje informacji o procesie, wskaż je zamiast wymyślać kroki.

Najpierw krótko opisz, jakie elementy kompozycji przeniesiesz ze screena, a następnie zbuduj sekcję. Zachowaj czytelną kolejność na mobile. Nie zmieniaj innych sekcji ani globalnych stylów. Nie dodawaj animacji lub interakcji, których nie da się ustalić na podstawie statycznego screena.

Na końcu sprawdź sekcję w przeglądarce na desktopie i mobile oraz podsumuj wprowadzone zmiany.
Iteruj sekcja po sekcji w Claude

Włącz Grid Guides. Gdy chcesz zmienić element, najedź na niego i skopiuj identyfikator komponentu. Przy zmianach layoutu określaj dokładnie, od której do której kolumny ma znajdować się każdy element.

Każdy prompt powinien dotyczyć jednej sekcji, komponentu albo animacji. Możesz pracować w 2–3 wątkach równolegle, jeśli ich zakresy nie dotykają tych samych plików i elementów.

Przykład / kolor przycisku
Zaktualizuj tylko komponent `[IDENTYFIKATOR PRZYCISKU]`. Zmień jego kolor tła na `[KOLOR LUB TOKEN]` i dobierz czytelny kolor tekstu. Zachowaj istniejące wymiary, typografię oraz stany hover i focus. Nie zmieniaj pozostałych przycisków ani globalnej palety. Po zmianie sprawdź rezultat w przeglądarce.
Przykład / układ na gridzie
Zaktualizuj tylko sekcję `[IDENTYFIKATOR SEKCJI]`. Na desktopie umieść blok tekstowy w kolumnach 1–4, a główny wizual w kolumnach 5–12. Zachowaj istniejące komponenty i spacing systemu. Na mobile ustaw najpierw tekst, a następnie wizual. Nie przebudowuj pozostałych sekcji. Sprawdź layout w przeglądarce.
Przykład / animacja timeline’u
Dodaj subtelną animację do timeline’u `[IDENTYFIKATOR KOMPONENTU]`. Podczas scrollowania kolejne elementy mają pojawiać się sekwencyjnie przez zmianę opacity i przesunięcie w osi Y. Zachowaj czytelność, aktualny layout i płynność na mobile. Uwzględnij `prefers-reduced-motion` i nie zmieniaj innych komponentów. Po implementacji przetestuj efekt w przeglądarce.
Przykład / praca z inspiracją
Pracuj tylko nad sekcją `[IDENTYFIKATOR SEKCJI]`. Załączoną inspirację wykorzystaj jako referencję dla `[KOMPOZYCJI / TYPOGRAFII / MOTION / SPOSOBU POKAZANIA PRODUKTU]`, ale nie kopiuj jej dosłownie. Zachowaj komponenty, tokeny i branding Mecha. Najpierw krótko opisz plan zmiany, następnie go wdroż i sprawdź rezultat w przeglądarce.
Szybki poradnik

Jak sprawnie budować z AI

Pracuj maksymalnie w 2–3 wątkach

Osobne wątki mogą dotyczyć np. copy, assetu i animacji. Nie otwieraj kilkunastu rozmów, nad którymi trudno zapanować.

Rozdzielaj zakresy

Nie zlecaj dwóm agentom jednoczesnej zmiany tego samego komponentu, pliku ani wspólnych tokenów.

Opisuj konkretny rezultat

Podaj identyfikator komponentu, cel zmiany, kolumny gridu i elementy, których agent nie powinien ruszać. „Zrób ładniej” nie wystarczy.

Dobieraj model do zadania

Mocniejszego modelu używaj do strategii, architektury, komponentów i animacji. Szybszy wystarczy do copy, spacingu i drobnych poprawek.

Nie czekaj bezczynnie

Gdy agent buduje wireframe, zbieraj inspiracje, rób screenshoty i przygotowuj assety do kolejnej iteracji.

Inspiracja potrzebuje instrukcji

Wklejając referencję do Claude, napisz, czy chodzi o kompozycję, typografię, motion, asset czy zachowanie komponentu.

Iteruj małymi zmianami

Przed większą zmianą upewnij się, że projekt działa. Pracuj sekcja po sekcji i po każdej zmianie sprawdzaj efekt w przeglądarce.

Problem techniczny? Zgłoś go

Jeżeli projekt nie startuje, terminal pokazuje błąd albo integracja nie działa, zgłoś to prowadzącemu zamiast tracić dużą część warsztatu na diagnozę.
